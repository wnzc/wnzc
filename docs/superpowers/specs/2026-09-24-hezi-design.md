# 《字谜》（合字谜）设计文档

日期：2026-09-24 · 状态：已批准范围（v1）· 作者：与用户共同头脑风暴

## 1. 一句话定位

> 给你 2~4 个汉字字根，摆出结构、组成新字——规则 10 秒学会，烧脑来自"结构 × 字根 × 词义"三重约束同时满足。

中文独有的益智 H5：合体（字根拼字）为主线，拆体（找字中藏字）与换根（同旁家族）为副线。

## 2. 目标 / 非目标

**v1 目标**
- 单文件 H5：`src/newGame/hezi.html`（零构建、无依赖，符合 newGame 既有约定）
- 70 个关卡：合体 40（2 字根 15 / 3 字根 15 / 4 字根+生僻 10）、拆体 15、换根 15；首 5 关教学
- 120 字启动字典（含字根分解、结构码、提示词、难度层），全部逐条校验
- 计分（次数/提示惩罚/生僻 ×2）、"今日新字 +1"（localStorage）、分享卡（canvas PNG）、每日一关（按日期确定性抽取）

**v1 非目标（v2 再议）**
- 盲拼硬核模式（字根 5s 后隐藏）、打字输入关、排行榜、音效、后端（每日一关纯前端日期种子，无服务端）

## 3. 工程约定（继承 `src/newGame/SPEC.md`）

- 纯 HTML5 + CSS3 + 原生 JS，单文件；Noto Sans SC；移动端优先响应式
- 视觉：深色渐变底 `#1a1a2e → #16213e → #0f0f23`；强调色 `#FFD93D / #FF6B6B / #4ECDC4`；按钮渐变+悬停动效；弹窗毛玻璃
- 注册两处：`src/newGame/index.html`（游戏合集卡片）+ 根目录 `index.html` 工具箱卡片（`{ title, desc, icon, link }` 一行）

## 4. 核心玩法循环

### 4.1 合体（主线）
1. 关卡卡显示：字根托盘（2~4 片字根瓦，同字根可重复，如 林=木+木）+ 提示词（高频词，如"轻歌曼舞"）
2. 选**结构模板**：关卡限定 1~4 个候选模板。模板随字根数：
   - 2 字根：左右 / 上下
   - 3 字根：左中右 / 上下中 / 品形（上+下左+下右）
   - 4 字根：器形（上 1 + 下 3，如 器=口+犬×3）
   模板 = 一组有序槽位；槽位顺序是假设的一部分（木+寸→村 是"木左寸右"）。
3. 拖字根瓦进槽（点选→点槽，或 pointer 事件拖拽；点已放瓦可撤下）
4. 点"成字"→ 精确验证（见 §5）
5. 成功：瓦片收拢成字动画 + 大字 + 一字小传 + 得分 + 分享卡按钮 + 下一关

**烧脑本质**：假设空间 = 模板 × 排列（有界、可枚举），每次"成字"精确检验一个假设，反馈三态（§5.3）——像侦探推理而非填字。

### 4.2 拆体
大字放大展示（如「蠢」），候选小字池（含干扰项，如 春/虫/目/田），逐项点选验证"此字是否藏于大字中"；找全目标字（1~2 个，带诗意指代，如"一个生长的，一个爬行的"）过关。点错计入次数。

### 4.3 换根（家族关）
固定一侧部件（如「青」定在右），N 个偏旁槽对应 N 个词槽（如 日/氵/米/讠 ↔ 晴朗/清亮/精神/请求）；拖偏旁到偏旁槽，每个位置即验证一次"该偏旁+青能否填入对应词"；全对过关。

## 5. 数据模型与可解性保证

### 5.1 字典条目（hezi.html 内 `const DICT`）
```js
{ ch:"曼", comp:["罒","日","又"], struct:"TMB", tier:3,
  hints:["轻歌曼舞","曼妙"], rare:false, bio:"从罒从日从又，天幕延展之意" }
```
- `struct` ∈ {LR, TB, LMR, TMB, PIN, QI}；`comp` 与槽位一一对应（有序）
- 拆体字额外：`hidden:["春","虫"]`；换根字：`family:["晴","清","精","请"], words:["晴朗","清亮","精神","请求"]`

### 5.2 关卡生成（载入时，从 DICT 派生，非手写）
- 索引：`(struct, comp 有序序列) → 字集`；字根多重集相同的字归入同一"多解族"
- 单解关：字集大小 = 1；多解关：字集 ≥ 2（答案集 = 整个字集，全找齐才满分，提示词指向主解）
- 模板候选 = 该字根多重集下可能有效的结构集合（由索引反推，无解模板不给）
- **结构保证**：每关可解性由索引数学上保证，不存在"死关"；难度层（tier 1/2/3）由字根数 + rare 决定
- 70 关的分配表（模式 × tier）写死在关卡配置中，指向 DICT 条目

### 5.3 验证反馈（合体）
| 状态 | 条件 | 反馈 |
|---|---|---|
| 无此字 | 键不在索引 | "无此字，重摆" |
| 字对味不对 | 键命中字 X，但提示词指向族内另一字 Y | "写的是「X」，词里要的是「Y」" |
| 过关 | 命中族内任意字；命中提示词所指 = 主解 | 成功 + 小传 |

### 5.4 数据校验
- `DICT.selfCheck()`：断言每条目 struct 合法、comp 长度与 struct 槽数一致、拆体 hidden 非空、家族 words 与 family 一一对应；开发态（`?dev=1`）载入即跑，UI 显示结果
- 120 字字典在实现期人工逐条复核（字根分解正确性、提示词高频性、小传一句）；复核通过才允许入库

## 6. 难度与教学
- 前 5 关教学：手把手演示"选模板 → 拖字根 → 成字 → 三态反馈"，提示词给全、模板只给 1 个（无选择压力）
- 提示阶梯 3 级（每用 1 次扣 10 分）：① 语义暗示 → ② 结构暗示 → ③ 直给摆法；连续失败 3 次自动解锁 ①
- 生僻字（rare:true）得分 ×2，通关后授予"字认主"头衔（累计解锁）

## 7. 计分 / 进度 / 元游戏
- 每关基础 100：每次失败 −5（下限 10），每次提示 −10；首解"完美"= 0 失败 0 提示（徽章）
- 进度（当前关、逐关得分）与"今日新字 +1"（当日首次接触的字）存 localStorage
- 每日一关：种子 = 日期 → 确定性抽 1 关，页面顶栏常驻入口；解出后展示"今日新字 +N"

## 8. 分享卡
canvas 750×500 PNG：深色底、字根瓦 + 成字大字 + 提示词 + "N 次命中 · M 次提示 · SSs" + 落款"《字谜》· 字谜工坊"；`toDataURL` 下载按钮（H5 无自动分享，另附"复制文字"）。

## 9. UI 布局（移动端优先）
```
[← 合集] 字谜          今日新字 +3
关卡 1-5 · 合体        「轻歌____舞」
[罒][日][又]          托盘（可拖）
模板：左右 / 上下中    （chip 切换）
┌─字板（槽位网格，虚线空槽）─┐
[成字]  [提示 ▸3] [重置]
```
成功弹窗（毛玻璃）：大字 + 小传 + 得分 + [分享卡] [下一关]。关卡列表页：70 节点按 tier 分组，灰/亮状态。

## 10. 边界与异常
- 同字根重复（林=木+木）：瓦片是独立对象，同形可多枚
- 字根异体（罒≈目、氵≈水）：按显示字形入库，小传中说明
- 生僻字字体缺失：Noto Sans SC 缺字时回退系统字体（渲染前用 `document.fonts` + 试画检测）
- 触屏：全部交互 pointer events 双通道（点选/拖拽），禁双击缩放（`touch-action`）
- 多解族中"无此字"的边界：多解族外的结构键不存在 → 同三态反馈，无需特判

## 11. 测试策略
- 无测试框架（单文件约定）：`DICT.selfCheck()` + 生成器自洽断言（每关可解、答案数已知）在 `?dev=1` 下跑
- 手动 QA 清单：首 5 关教学流、拖拽/点选双通道、三态反馈文案、分享卡渲染（390px 窄屏 + 桌面）、localStorage 进度恢复、每日一关日期确定性
- 字典正确性：实现期人工复核 + 抽查 30 条（字根分解、提示词）

## 12. 验收标准
1. `hezi.html` 单文件载入，70 关全部生成且逐关有已知解
2. `?dev=1` 下 selfCheck 全绿

4. 分享卡 canvas 输出 PNG 正确
